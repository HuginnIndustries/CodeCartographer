# E11 pilot — end-to-end loop through real records (2026-09-22)

Refs #409. Branch `feat/e11-e2e`. This note records what was actually
exercised, what was not, and where the tests had to bend to the contract.

## What ran

`tests/engineering-e2e.test.mjs` drives a real `.codecarto/engineering/`
namespace (`openStore` in a temp dir; nothing mocked) through the functions
each earlier evolution shipped, in host order:

`liftSlices` (E09/E10) → `buildChangeBrief`, `buildChangePlan`,
`planReadiness` (E04) → `store.put` change/slice/attempt (E01) →
`collectSnapshot`, `candidateMayBindAcceptance`, `diffSnapshots` (E02) →
`ingestProof` ×2 (E03) → review record (E07) → `evaluateAcceptanceGate`,
`describeGateOutcome` (E06) → `planTraverseStep` (E08).

Planning text and the tree contents come from
`tests/fixtures/engineering/pilot/` (synthetic). Record shapes are read from
`tests/fixtures/engineering/v1/valid/` and mutated as copies, as
`tests/engineering-gates.test.mjs` does. Every negative control first runs the
happy-path helper to `may-accept` in its own store, so a refusal cannot come
from an unrelated defect.

## What was NOT done

- **F01, the preregistered feature pilot, was not run through a live host in
  this PR.** Nothing here executes a check, captures a real tree, or
  presents anything to a person. B01 (the real-fix half) already ran at
  c4030a4; the feature half of the pilot stays open under #409.
- **No human acceptance occurred.** N08 proves the loop stops before one;
  no test writes an approval record, and `VERIFIED_ACCEPTANCE_INTEGRATIONS`
  is unchanged (empty). The pilot fixtures are test data, not evidence of a
  gate.
- **N03 is not "edit the plan under a live attempt".** The store makes
  attempts immutable, so a changed input is expressed as a superseding
  attempt with a new input digest. That is the mechanism E01/E03 provide;
  no timestamp staleness rule exists and none was invented.
- **R04 on the accept path.** `describeGateOutcome` names obligations only
  when refusing. The happy-path test asserts the per-obligation account via
  `ingestProof`'s discharge outcomes and the slice's declared obligations;
  the "gate names the obligation" assertion lives on the refusal path (N01,
  N02, N03).
- **Second-change baseline is by reference, not enforced.** The contract has
  no field that forces `attempt.baseline_snapshot_id` to name another
  change's candidate; R09 asserts what the records say, not that the core
  checks it.
- **Provenance is fixture-attested.** `host-tool-result` provenance is
  copied from the shipped proof fixture; no adapter produced it.
