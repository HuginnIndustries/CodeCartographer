Why it works

A workflow, not a vibe.

Every phase has a defined output, explicit completion criteria, and a handoff into the next step. That structure makes the analysis reusable instead of disposable.

Phase-gated analysis

Start with the system map. Then move into defects, contracts, and protocols with the architecture already pinned down.

Evidence levels

Findings are marked as observed fact, strong inference, portability hazard, or open question so confidence stays visible.

Cross-session continuity

status.yaml and the thread log let a fresh LLM session pick up exactly where the last one stopped.

Pipelines

Scale the depth to the job.

The default run is a 6-phase full audit, but CodeCartographer also supports lighter passes when you only need orientation, behavior recovery, or defect hunting.

6 phases

Full with audit

Complete reverse-engineering with a defect triage phase before porting and reimplementation planning.

  1. Architecture
  2. Defect scan
  3. Contracts
  4. Protocols
  5. Porting
  6. Reimplementation spec

Best when you need a reusable understanding bundle before maintaining, porting, or rebuilding a system.

Outputs

The bundle you end up with.

Instead of one summary blob, the workflow leaves behind artifacts that different people can actually use: engineers, reviewers, maintainers, and the next model session.

Architecture map

Layers, public surfaces, runtime lifecycle, dependency direction, and porting priorities.

Defect report

Multi-pass scan covering logic, error handling, concurrency, security, API drift, and config risks.

Behavioral contracts

User-visible behavior, defaults, side effects, error modes, and black-box acceptance checks.

Protocols and state

Events, state machines, persistence notes, compatibility hazards, and internal message flow.

Porting bundle

A synthesis layer that ranks what matters, what is risky, and what needs special treatment in a rewrite.

Reimplementation spec

A language-agnostic build plan with modules, acceptance scenarios, and known unknowns.

Compatible with Pi-mono, Codex, Claude Code, OpenCode, Cursor, Windsurf, Aider, and other agents with file access.

Install and distribute

Start with the Pi-mono extension, or use the drop-in workspace anywhere else.

CodeCartographer was packaged first as a Pi-mono extension. The core toolkit still stays dependency-free, so you can also drop .codecarto/ into Codex and other file-aware coding agents.

Install in Pi-mono

Use the repository itself as a package and expose the extension commands directly inside Pi.

pi install /absolute/path/to/CodeCartographer
pi -e /absolute/path/to/CodeCartographer/extensions/codecarto/index.ts

Pi command workflow

Initialize a repo, queue the next phase, validate output, and mark the current phase complete.

/codecarto-init full-with-audit
/codecarto-next
/codecarto-validate
/codecarto-complete

Drop-in .codecarto/

For Codex, Claude Code, Cursor, OpenCode, Windsurf, Aider, and other agents that can read and write workspace files.

cp -r /path/to/CodeCartographer/.codecarto /path/to/your-repo/
